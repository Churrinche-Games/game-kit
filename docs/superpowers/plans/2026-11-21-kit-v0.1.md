# Electro Chicken kit v0.1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The first tagged version of `@electrochicken/kit`: the shared pieces Bichoku needs for its first Play release (storage, Spanish/English, sound effects, rating prompt, feedback link, More games list, and the game menu that ties them together).

**Architecture:** A TypeScript-source package (no build step) in `~/src/game-kit`, consumed by games as a git dependency pinned to a tag. Pure logic in `.ts` files with colocated Vitest tests; the one React component (the menu) and the thin Web Audio and native wrappers have no tests, by convention. Each module is a subpath export (`@electrochicken/kit/storage`, …).

**Tech Stack:** TypeScript ~7.0, React ^19.3 (peer), Vitest ^5.1, oxlint ^1.90, Node 26. Optional native peers: `@capacitor/core` ^8.6, `@capacitor-community/in-app-review` ^8.0.

**Spec:** [docs/superpowers/specs/2026-11-21-portfolio-design.md](../specs/2026-11-21-portfolio-design.md), sections "Shared kit", "Repos and code sharing", "Art and sound", "Decided with Juan".

## Global Constraints

- Node 26: `export PATH="$HOME/.nvm/versions/node/v26.13.1/bin:$PATH"` in every shell.
- Dependency majors pinned to the ones in `~/src/sudoku/package.json`: react ^19.3.1, typescript ~7.0.2, vitest ^5.1.0, oxlint ^1.90.0, @types/react ^19.3.0, @types/node ^24.19.2.
- The kit ships `.ts`/`.tsx` source; `package.json` `exports` point at source files. No `dist/`.
- Kit code never names a specific game, except as data in the More games list.
- Interface text exists in both `es` (rioplatense, voseo) and `en`.
- Storage keys are always `${appId}:<name>`; every storage access is guarded (blocked storage only means nothing is saved).
- Nothing in the kit requires Capacitor at import time on the web; native calls are guarded and swallow errors.
- TDD: failing test first, watch it fail, minimal code, pass. Commit after each task. No AI attribution in commits.
- Done means `npm test && npm run lint && npm run build` pass.

## Review Focus

1. **Blocked or throwing storage** (private mode, quota): every load returns its default, every save is a no-op, nothing throws. Tested in Task 1 and reused by every module's tests through `throwingStore()`.
2. **Unexpected device languages** (`pt-BR`, `es-419`, uppercase `ES-ar`, empty list): Spanish for any `es*` tag, English otherwise. Tested in Task 2.
3. **Rating prompt on first launch or asked twice:** never during the first session, never more than once, even across restarts. Tested in Task 4.
4. **Sound before any user gesture or with no Web Audio** (WebView without `AudioContext`): `play` is a silent no-op, never throws. Tested in Task 3.
5. **Special characters in the feedback mail** (`&`, `?`, accents in Spanish subject): the `mailto:` link stays valid and decodes to the exact subject. Tested in Task 5.

### Task 3: Sound effects

**Files:**
- Create: `src/sound/sound.ts` (pure: notes, presets, setting), `src/sound/sound.test.ts`, `src/sound/player.ts` (Web Audio, untested)
- Modify: `package.json` (`"./sound": "./src/sound/sound.ts"`, `"./sound/player": "./src/sound/player.ts"`)

**Interfaces:**
- Consumes: Task 1 storage helpers
- Produces:
  - `type Tone = { freq: number; toFreq?: number; ms: number; at?: number; wave?: OscillatorType; gain?: number }` (`at` = start offset in ms, default 0; `wave` default `'triangle'`; `gain` default 0.15)
  - `type Sound = readonly Tone[]`
  - `noteFreq(note: string): number`: scientific pitch, `A4` = 440, equal temperament, sharps and flats (`'A#4'`, `'Bb4'`); throws `Error` on an invalid note
  - `arpeggio(notes: readonly string[], stepMs: number, toneMs: number, wave?: OscillatorType): Sound`: tone `i` at `at = i * stepMs`
  - `soundLength(sound: Sound): number`: max of `(at ?? 0) + ms`
  - `SOUNDS: { tap: Sound; place: Sound; error: Sound; win: Sound }`, with exactly these values:
    - `tap`: `[{ freq: 660, ms: 40, gain: 0.12 }]`
    - `place`: `[{ freq: 520, toFreq: 780, ms: 90, gain: 0.18 }]`
    - `error`: `[{ freq: 220, toFreq: 160, ms: 180, wave: 'square', gain: 0.06 }]`
    - `win`: `arpeggio(['C5', 'E5', 'G5', 'C6'], 90, 160)`
  - `loadSoundOn(store: KeyValue, appId: string): boolean` (default `true`, key `${appId}:sound`); `saveSoundOn(store, appId, on: boolean): void`
  - In `player.ts`: `createPlayer(makeContext?: () => AudioContext | null): { play(sound: Sound): void; setEnabled(on: boolean): void; enabled(): boolean }`. The default `makeContext` returns `new AudioContext()` when `globalThis.AudioContext` exists, else `null`. The context is created lazily on the first `play` (that's a user gesture) and resumed if suspended. Each tone gets an oscillator and a gain envelope: a 5 ms linear attack to `gain`, an exponential ramp to 0.0001 at `ms`, and an exponential frequency ramp to `toFreq` when set. `play` is a no-op when disabled, when there's no context, or when anything throws.

### Task 4: Rating prompt rules

**Files:**
- Create: `src/rating/rating.ts`, `src/rating/rating.test.ts`, `src/rating/requestReview.ts` (native, untested)
- Modify: `package.json` (`"./rating": "./src/rating/rating.ts"`, `"./rating/native": "./src/rating/requestReview.ts"`)

**Interfaces:**
- Consumes: Task 1 storage helpers
- Produces:
  - `type ReviewState = { sessions: number; wins: number; asked: boolean }` (key `${appId}:review`, default `{ sessions: 0, wins: 0, asked: false }`; a malformed saved value counts as the default)
  - `const REVIEW_AFTER_WINS = 3`
  - `shouldAsk(s: ReviewState): boolean`: `!s.asked && s.wins >= REVIEW_AFTER_WINS && s.sessions >= 2`
  - `startSession(store: KeyValue, appId: string): ReviewState`: increments and saves `sessions`. Call once per app launch.
  - `recordWinForReview(store: KeyValue, appId: string): boolean`: increments `wins`. If `shouldAsk` is now true, sets `asked` and returns `true`. Saves either way.
  - In `requestReview.ts`: `requestReview(): Promise<void>`, which runs only when `Capacitor.isNativePlatform()` and then calls `InAppReview.requestReview()` from `@capacitor-community/in-app-review`. It resolves even on error. Use dynamic `import()` for both packages so web builds without them still work.
